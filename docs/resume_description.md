# 简历项目描述

## 1. 项目名称

工业设备运维知识库 RAG 与故障诊断 Agent 系统

## 2. 项目背景

本项目面向企业设备运维知识检索与故障诊断场景，模拟现场工程师在遇到设备报警、过载、异常停机等问题时，需要同时查询设备说明书、SOP、历史报警和维修工单的工作流程。

项目通过 RAG 技术解决非结构化设备文档检索问题，通过 MySQL 管理设备、报警、维修和报告等结构化业务数据，并通过 Function Calling 与诊断流程编排实现可追溯的故障分析和 Markdown 诊断报告生成。

## 3. 技术栈

- Python
- FastAPI
- LangChain
- Chroma
- MySQL
- SQLAlchemy
- DeepSeek API
- 智谱 Embedding API
- Function Calling
- RAG

## 4. 项目职责

- 设计并实现基于 FastAPI 的后端接口，包括文档上传、RAG 问答、设备查询、工具调用问答、故障诊断和报告历史查询。
- 构建工业设备文档 RAG 流程，完成文档解析、切块、Embedding、Chroma 向量存储、相似度检索和来源返回。
- 设计 MySQL 业务数据模型，建立设备台账、报警记录、维修记录、聊天历史和诊断报告等表结构。
- 封装知识库检索、设备信息查询、报警记录查询和维修记录查询等工具函数，为 Function Calling 提供可复用能力。
- 接入工具调用问答接口，返回并保存 `tool_calls`，支持观察工具名称、入参、执行状态和结果摘要。
- 实现故障诊断流程编排，整合知识库、设备基础信息、历史报警和历史维修记录，生成结构化诊断结论。
- 实现 Markdown 诊断报告生成和 MySQL 持久化，支持按 `report_id` 查询单份报告和按 `session_id` 查询报告列表。
- 优化知识库外问题处理逻辑，在无可靠依据时返回空 sources 或明确提示，避免编造引用和业务数据。

## 5. 项目亮点

- RAG 知识库问答：支持设备说明书、维修手册、SOP 等文档的检索增强问答。
- Chat 模型与 Embedding 模型解耦：DeepSeek 负责文本生成，智谱 Embedding 负责向量化。
- MySQL 业务数据结合：将设备台账、报警记录、维修工单与知识库问答结合，贴近工业运维场景。
- Function Calling 工具调用：将知识库检索和数据库查询封装成可调用工具，提高系统扩展性。
- `tool_calls` 可观测：返回并保存工具调用记录，便于调试、验收和面试展示。
- 诊断报告生成：基于多源证据生成结构化 Markdown 诊断报告。
- 报告历史追溯：报告保存到 MySQL，支持按报告编号和会话编号查询。
- 防止编造来源：知识库外问题或缺少设备编号时明确提示，不伪造 sources、设备信息、报警记录或维修记录。

## 6. 简历精简版

工业设备运维知识库 RAG 与故障诊断 Agent 系统：基于 FastAPI、LangChain、Chroma、MySQL 和 Function Calling，构建设备文档知识库问答、设备台账与历史报警/维修查询、工具调用问答和故障诊断报告生成能力。项目支持 sources 引用返回、tool_calls 可观测、聊天历史保存、Markdown 报告持久化和按会话追溯，针对知识库外问题明确返回无可靠依据，避免编造来源。

## 7. 面试展开版

我做的项目是一个面向工业设备运维场景的知识库 RAG 与故障诊断 Agent 系统。它模拟现场工程师遇到设备故障时，需要查设备说明书、维修手册、SOP、历史报警和维修工单的场景。项目的目标不是做一个通用聊天机器人，而是把大模型能力和工业运维业务数据结合起来，形成一个可追溯的故障诊断后端系统。

技术上，我使用 FastAPI 搭建接口层，提供文档上传、RAG 问答、设备查询、Function Calling 工具问答、故障诊断和报告查询接口。RAG 部分使用 LangChain 进行文档解析和切块，使用智谱 Embedding API 生成向量，并通过 Chroma 做持久化向量检索。Chat 生成部分使用 DeepSeek API，Embedding 和 Chat 模型分开配置，避免把聊天模型强行用于向量化任务。

在业务数据层，我使用 SQLAlchemy 和 MySQL 建模了设备台账、报警记录、维修记录、聊天历史和诊断报告等表。阶段三中，我把知识库检索、设备查询、报警查询和维修查询封装为工具函数，提供 Function Calling 接口，并返回 `tool_calls`，让工具调用过程可观察、可调试、可保存。

阶段四中，我在工具能力基础上实现了故障诊断流程编排。系统会根据用户问题和可选设备编号，查询设备基础信息、检索知识库、查询历史报警和维修记录，整合成 `evidence`，再生成结构化诊断结论和 Markdown 报告。报告会保存到 MySQL，支持按 `report_id` 查询单份报告，也支持按 `session_id` 查询会话下的报告列表。

这个项目目前是一个模拟工业设备运维场景的求职展示项目，没有宣称生产级上线或真实企业部署。但它覆盖了 RAG 应用开发中比较关键的工程链路，包括知识库检索、业务数据库、工具调用、可观测性、报告生成和历史追溯，也体现了我把控制工程背景和大模型应用开发结合的思路。
